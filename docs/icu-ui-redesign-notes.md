# ICU Alert System 界面重设计建议

## 结论

目前系统的主要问题不是“功能不够”，而是**功能、信息和解释同时平铺**：用户进入页面后既要判断风险、阅读证据、理解模型、选择筛选条件，又要决定下一步动作。ICU 场景中这会增加扫描时间和决策负担。

重设计目标：让每个页面先回答一个问题。

- 首页：我现在最该做什么？
- 患者总览：谁最需要先看？
- 患者详情：这个患者发生了什么？
- 预警中心：哪些事件需要确认与闭环？
- 交接班：哪些变化必须交代？
- AI 助手：围绕当前患者完成一个明确任务。
- 科研/管理：再进入低频、复杂工具。

## 当前体验诊断

1. **卡片承担过多职责**：患者身份、生命体征、器官风险、预警摘要、证据链、设备管路、护理提醒、Bundle 都塞进总览卡片。
2. **同级入口太多**：侧栏大量模块平铺，用户先学习系统结构，才能开始工作。
3. **筛选条件与工作意图混在一起**：科室、风险、标签、领域、优先级、轨迹预测同时出现。
4. **解释文字抢占注意力**：大量“这是什么、如何理解”的说明出现在高频工作页，而不是按需展开。
5. **重要信息重复**：危急数量、重点关注、风险分区、预警卡片反复表达同一风险。
6. **缺少主动作**：页面展示很多结果，却不突出“查看、确认、复评、交接”等下一步。

## 全局信息架构

建议把一级导航从“功能清单”改为“临床工作流”：

1. 今日工作
2. 患者
3. 预警
4. 交接班
5. AI 助手
6. 更多（查房、呼吸、营养、MDT、科研、配置）

按角色默认进入不同的“今日工作”，但共享同一套患者与预警模型。低频模块不要与患者总览争夺一级导航位置。

## 患者总览重设计

### 页面只保留四层

1. **当前结论**：3 位需要立即处理。
2. **快捷范围**：全部、危急、预警、机械通气、待办。
3. **优先级患者列表**：床号、姓名、3 个核心体征、当前最重要问题、本班任务、状态。
4. **辅助区**：优先关注 Top 3、本班即将到期任务。

### 从总览移出的内容

以下内容进入患者详情或右侧快速抽屉：

- 器官风险雷达与全部风险指纹
- 完整 AI 摘要、病理生理链、全部证据
- 设备/管路明细
- Bundle 全量项目
- 全部护理记录
- 轨迹预测解释

总览负责“发现与进入”，详情负责“理解与处置”。

### 交互原则

- 默认按**处置优先级**排序，不按床号排序。
- 点击患者先开快速抽屉；需要深入时再进入详情。
- 同一时间最多突出一个主动作。
- 筛选项默认不超过 5 个；高级筛选收进弹层。
- 危急/预警不仅用颜色，还用文字和左侧风险条。
- 文字采用“结论 + 证据按需展开”，避免整段说明常驻。

## 各模块统一模板

### 高频工作台（首页、总览、预警、交接班）

- 顶部：一句话当前结论
- 中部：主任务列表
- 右侧：即将到期 / 异常
- 详情：抽屉或二级页面

### 单患者页

- 固定患者头：身份、过敏、隔离、关键装置
- 首屏：当前问题、核心趋势、建议动作
- 二级标签：趋势、检验、用药、设备、护理、文书
- AI 只在上下文中出现，不单独堆成长报告

### 复杂工具（科研、配置、AI 运营）

- 使用步骤式流程：选择对象 → 配置 → 预览 → 执行/导出
- 每一步只展示当前所需字段
- 高级参数默认折叠，并提供安全默认值

## 建议落地顺序

1. 先改 `PatientOverview.vue` 与 `PatientOverviewCard.vue`：切换为表格/紧凑卡片，移除总览中的深层临床解释。
2. 把完整风险摘要与证据复用到患者快速抽屉或 `PatientDetail.vue`。
3. 收敛 `SideNav.vue`：一级入口控制在 5–6 个，其余放入“更多”。
4. 建立统一设计令牌：间距、字号、状态色、按钮层级、抽屉和空状态。
5. 用医生、护士各 3 个真实任务做可用性测试：找到危急患者、确认预警、完成交接；记录完成时间与误点。

## 验收指标

- 进入总览 5 秒内能指出首要患者。
- 首屏常驻筛选不超过 5 个。
- 单患者行/卡常驻文字不超过 3 行解释。
- 危急患者进入详情不超过 1 次点击。
- 高频任务完成路径不超过 3 步。
- 无需阅读说明文字即可完成核心任务。
